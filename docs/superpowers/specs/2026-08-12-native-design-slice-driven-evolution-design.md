# Native Design 产品切片演进与渐进清理方案

> 日期：2026-08-12
>
> 路线状态：`confirmed`
>
> 新 Phase A：`open`
>
> 产品主线：继续确认并补充新的 Phase A
>
> 清理策略：切片内死代码强制删除；跨切片残留进入唯一退役账本；不可逆数据退役独立审批

## 1. 决策摘要

Multica 取消独立、一次性的 Open Design V1 破坏性移除 Phase B，不再把全仓库旧符号清零、跨层原子删除和 migration 877 作为当前产品阶段。

后续只沿 Native V2 产品能力推进。每个功能切片在证明完整替代关系后，必须删除切片内部已经无调用的 V1/Worker 分支、fallback、旧配置和旧测试；发现跨切片、跨数据生命周期或仍有外部消费者的残留时，不得扩大当前切片，必须登记到唯一退役账本。不得为了全仓库清零扩大到未触达模块。

`open_design_run`、non-V2 package rows、历史 archive/evidence/Preview 对象和 schema constraint 等不可逆数据退役，不进入普通功能切片。只有全部活动代码自然退出对应数据后，才允许提出独立规格、独立审批和独立验证。

## 2. 为什么替代独立 Phase B

独立 Phase B 需要同时修改 daemon、handler、service、router、SQL/sqlc、前端、配置、对象存储和数据库迁移。这些层之间存在强编译和部署依赖，必须一次性闭合；任何中断都会产生无法编译、无法验证或不可部署的中间状态。

这种计划从历史实现反推删除范围，缺少天然的用户价值边界。每删除一个底层符号都会继续发现更多调用方，范围不可预测，验证成本随依赖树扩散。

Native V2 产品切片则拥有明确的入口、输入、产物、失败语义和验收证据。以产品切片作为工作单元，可以先证明新能力，再删除被该能力完整替代的局部旧路径，使每次变更可理解、可测试、可回滚。

## 3. 已确认的路线边界

1. `2026-08-12-native-design-phase-1-closure-and-legacy-removal-design.md` 中独立 Phase B 路线被本方案替代；其中已经取得的 Phase A 自动化证据仍然有效。
2. `2026-08-12-open-design-v1-destructive-removal.md` 不再执行，原 Task 3–12 不得作为后续实现清单继续推进。
3. 后续开发只沿 Native V2 产品功能主线组织。
4. 每个 Native V2 功能切片必须删除切片内部已经无调用且被完整替代的旧路径；跨切片、跨数据生命周期或仍有外部消费者的残留进入唯一退役账本。
5. 不为了 clean grep、目录清空或旧名称归零而扩大当前功能范围。
6. 一个旧模块只有在没有活动调用方后，才允许整体删除。
7. 数据库行、表、约束和对象存储历史数据的不可逆清理必须单独提出、审批和验证。
8. 隔离分支 `feature/fengchen-fixed-v2` 只保留为取消路线的 checkpoint，不合入 `feature/fengchen`，不作为后续实现基线，也不计入产品进度。
9. 新 Phase A 的目标、切片和验收由后续产品讨论补充；本方案不提前代填需求。
10. 本规格优先于两份标为 `superseded` 的 Phase B 文档。旧文档中的任务、命令和验收不得继承，除非被新的功能切片规格逐条引用。

## 4. 功能切片清理门禁

每个 Native V2 功能切片使用两级清理规则：切片内部已经无调用的死代码必须删除，并阻塞切片完成；跨切片、跨数据生命周期或仍有外部消费者的残留不得扩大当前切片，必须进入唯一退役账本。只有满足以下条件，才允许删除对应旧残留。

### 4.1 替代关系明确

必须指出旧入口、分支或数据读取由哪个 Native V2 入口完整替代。不能因为文件名、包名或注释含 Open Design/V1 就判定可删除。

### 4.2 调用范围有界

开始实现前列出当前切片触达的 API、daemon、handler/service、数据、Web/Desktop 和测试范围。清理只能发生在这份范围内；新增范围必须重新评估，而不是沿依赖树无限扩张。

### 4.3 V2 正向证据先通过

必须先证明 Native V2 正常流程可用，再删除旧路径。测试应通过真实边界验证行为，不能只测试内部 helper。

### 4.4 失败和安全语义不退化

取消、失败、重试、坏包、越权、对象存储失败和 completion 重放必须继续保护 draft/saved。删除旧分支不得产生空成功、半完成内容、静默 fallback 或权限放宽。

### 4.5 活动消费方先迁移

Server、daemon、Web/Desktop 和 API schema 中属于当前切片的活动调用方必须先迁移到 V2。只要仍有活动调用方，就不能删除提供方。

### 4.6 建立局部负向合同

当前切片内的旧入口必须明确拒绝、不可达或不再注册。不得留下半活动 alias、双读、兼容转换或隐藏 fallback。

### 4.7 普通功能切片不退役历史数据

功能 PR 只允许停止新的旧链路读写并删除死代码，不删除历史行、对象或数据库表，也不收紧会拒绝现有历史数据的 schema constraint。

### 4.8 验证范围跟随改动

至少运行当前切片的 Go/TypeScript 定向测试、相关 package 回归、typecheck 和 GitNexus `detect_changes`。如果切片影响通用 Agent lifecycle，还必须证明非设计任务的 claim、execute、complete、fail、cancel 和恢复没有变化。

### 4.9 一个切片一个可回滚提交集

不能把多个独立旧模块堆进同一次删除。每个切片应能作为整体回滚，不依赖恢复另一套旧运行链路。

### 4.10 文档只记录事实

每个切片必须写明已清理的局部路径、仍然保留的旧模块、未处理的数据和实际验证结果。局部清理不得描述为 V1/Open Design 全面退役。

## 5. 唯一退役账本

`docs/product/design-center/native-v2-retirement-register.md` 是旧能力状态的唯一事实源。只在功能切片真实触达某项旧能力时增量更新，不预先盘点全仓库，也不按单个零碎 symbol 建项。

状态只使用：

- `active`：仍有新的旧链路读写，或外部消费者状态未知；
- `write-retired`：已停止新增旧数据，但仍读取历史数据；
- `unreferenced`：活动代码和已确认消费者均无调用，可以删除纯代码；
- `retired`：纯代码和活动接口已经删除；
- `data-pending`：活动代码已退役，历史行或对象等待独立审批清理。

每项记录旧能力、当前消费者、读写状态、V2 替代项、负责切片、删除阻塞项、证据、最后复核日期与 commit，以及下一状态的必要条件。

## 6. 切片硬停止条件

发现以下任一情况时，旧残留清理不得继续扩张，必须登记到退役账本：

- 需要进入第二个独立产品能力；
- 需要同时改变两个以上数据生命周期；
- 需要 destructive migration 或对象删除；
- 需要一次关闭多个不属于当前切片的旧 API；
- 需要修改通用 Agent lifecycle；
- 需要同时协调 Server、daemon、Web/Desktop 和数据库才能闭合；
- 无法形成一个独立回滚的提交集；
- 仍有旧 Desktop、CLI、MCP 或运维消费者；
- 新增范围超过计划批准的文件、符号、API 或数据集合。

唯一例外是新增依赖仅为当前切片内部的直接死代码，且不引入第二个业务能力或数据生命周期。此时必须补充 impact 和计划范围后再删除。

## 7. 每个功能切片的最低证据

每个新的 Native V2 功能切片至少提供：

1. V2 正向合同：验证真实 API、handler 或 daemon 边界，不能只测 helper；
2. 失败隔离合同：坏输入、失败、取消或存储异常不破坏有效状态；
3. 旧路径负向合同：切片内已替代旧入口不可达、拒绝或不再注册；
4. 范围外回归：列出并验证可能受影响的非本切片业务；涉及通用 daemon 时覆盖非设计任务生命周期；
5. 持久化不变量：按切片断言 workspace、project、task、draft/saved、digest 和对象引用；
6. 退役账本变化：记录条目的前后状态及仍存在的阻塞项；
7. 实际命令证据：定向测试、相关 package 回归、typecheck 和 `detect_changes`，未运行项明确写 `NOT RUN`；
8. 提交与回滚边界：当前切片能整体回滚，且不要求恢复另一套旧运行链路。

## 8. 兼容消费者规则

- 当前 Web/Desktop 代码迁移由功能切片负责。
- 已安装旧 Desktop、CLI、MCP 或运维调用不能仅凭代码 grep 判定消失。
- 缺少遥测时，不为删除旧 API 临时建设遥测系统；对应条目保持 `active` 或 `write-retired`，并记录“外部消费者未知”。
- 只有产品明确结束兼容窗口，或存在可复核证据证明没有活动消费者，才能转为 `unreferenced`。
